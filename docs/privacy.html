Privacy policy

Battery Sentinel Pro Netra (the app) and this website. Last updated: November 5, 2026. Developer contact: prayagideepak@gmail.com.

The app, in short

The app reads Android battery, charging, temperature, Bluetooth and related status for local displays and history. It does not create a user account or show ads. Some features make the network requests described below; not all information stays on the phone.

Feedback and automatic crash delivery

Manual feedback shows a disclosure before you choose to send. Separately, when a pending sanitized crash report exists, the app automatically tries to send it the next time it starts; this startup path does not ask for consent each time. A failed send is retried at a later start. The pending trace is removed after reported delivery success.

These reports go through FormSubmit to the developer's email inbox. Fields are app name, phone model, Android version, app version, and either your typed feedback (up to 1,000 characters) or a technical stack trace (up to 6,000 characters). Crash sanitization keeps exception classes and code locations, dropping exception messages. This reporting payload does not include contacts, photos, location, Bluetooth names, device IDs or battery history. Do not type sensitive personal information into feedback. Contact the developer to request deletion of a delivered report; automatic server-side deletion has not been established.

Location, weather and country context

With location access, the app can read last-known coordinates and use Android's geocoder for place context. The current resolver does not check the age of a last-known fix. For weather it sends coordinates rounded to two decimal places to Open-Meteo over HTTPS and caches the result for about 30 minutes. The weather provider receives those coordinates and ordinary connection metadata, including the source IP. Platform geocoding may use the device provider's network service. SIM/network country and device locale also supply country context.

Location and weather can retain last-known values. Turning off Android location permission prevents new protected location reads, but the current implementation can retain earlier coordinates for weather requests during the running process. Permission revocation should not be read as proof that all retained location use has stopped. Force-stopping the app in Android settings ends its current process and in-memory context. This is a current implementation limitation, not a promise of live or exact location.

Optional usage counter

Usage counting is off by default and can be switched off in Settings. When enabled, the app attempts daily and monthly UTC counter increments in Google Firestore. The body contains a counter document name and increment by one, not an install ID, account, location, battery history or device identifier. This counts observations, not unique people. Network services still receive ordinary connection metadata. Failed increments can retry on a later open.

Updates and stability diagnostics

Update checks read public release metadata from GitHub, with up-to-six-hour caching/backoff. Downloads open the BSPN page in Netra Ecosystem or a browser; this app does not download or install APKs itself.

Local stability diagnostics can include app/device/Android versions, event timestamps, issue/exception classes, sanitized app code locations and a battery/charging telemetry summary. A separate optional HTTPS stability endpoint can receive queued diagnostics if configured by the build; the default source configuration is blank. Do not assume the presence of local diagnostic files proves a configured remote destination. Ordinary internet requests reveal connection metadata to their service providers.

Local history and controls

Battery/session history, preferences and bounded logs are stored in private app storage. CSV/PDF export and sharing are user actions. Clear History is not a promise to erase every preference, learned value, crash file or previously exported document. Display/sync controls require their separate consent and applicable Android access; experimental secure-settings controls have additional limitations.

The website

  • Ratings, suggestions and complaints are public. What you type (stars or message, your phone model, Android version if given, and for ratings the name you choose or "Anonymous") is stored in Google Firebase and shown on the website. Please do not type personal details. You cannot edit an entry after sending; to have one removed, email the developer.
  • Replies from the team are public and signed "Netra by Prayagi Team".
  • Email address (optional) is sent privately to the developer to reply to you, and is never stored in the public database or shown.
  • Uploaded images or videos (optional, max 2 MB) are sent privately to the developer and never shown publicly.
  • Forms are delivered by the FormSubmit email service. Visits are counted with a free third-party counter. Downloads are counted by GitHub.
  • Website analytics (optional, consent-based). With your permission this website uses Google Analytics 4 to count visits. Microsoft Clarity recording is currently disabled on all pages, including forms. Nothing is loaded until you tap Accept on the consent banner; No thanks loads nothing, and your choice is remembered on this device. These website analytics are separate from the app's optional usage counter described above.

Permissions the app may ask for

Android access affects which features can run: notifications (alerts), Bluetooth (connected device list and battery), phone state (to avoid speaking over calls), usage access (recent app usage, not measured per-app energy), and system settings or audio settings only for optional features you switch on. You can revoke any permission in Android settings.

Your choices and contact

You can use the app without ever sending feedback. To ask about, correct or delete something you sent, email prayagideepak@gmail.com.
